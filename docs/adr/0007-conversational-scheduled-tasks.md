# ADR 0007：对话式定时任务

## 状态

已批准（用户于 2026-09-04 明确要求前后端实现定时任务）。

## 决策

定时任务以 PostgreSQL 为权威存储，API 提供用户作用域的创建、列表和状态变更接口。API 后台扫描到期任务，只负责原子认领并通过现有 generation Outbox 创建生成任务；真实模型请求仍只由 Worker 执行。

任务配置复用普通对话。推荐项先创建对话，前端在对话内动态生成问卷，确认后创建任务。配置对话与执行对话分离：用户点击“立即执行”时新建执行对话并将其设为当前执行对话；服务端定时触发时复用未归档的当前执行对话，不存在时创建新对话。

每次执行建立 `ScheduledTaskRun` 记录并关联 Generation。定时执行的 Generation 使用隔离上下文：结果在界面上追加到同一对话，Worker 却只把本次任务提示词发给模型，避免历史结果和用户追问污染后续执行。

## 后果

- 不在浏览器中保存权威调度状态。
- 不在 HTTP 请求处理器中运行模型请求。
- 定时点以 `taskId + scheduledFor` 唯一约束保证幂等，同一任务的前一次运行未结束时跳过当次触发。
- 前台通过用户级 SSE 接收任务终态，提供站内通知和执行对话入口。
